# Status

This file is the single source of truth for what InvestingExile contains. Every commit updates this file in the same commit.

## Now

- `backend/InvestingExile.sln` is a .NET 8 solution.
- Projects in that solution: InvestingExile.Domain, InvestingExile.Pipeline, InvestingExile.Api, InvestingExile.Tests.
- `InvestingExile.Domain` is the class library under `backend/`. It holds `League`, `Item`, `PriceSnapshot`, and `AppDbContext`. Item identity is category + name + variant. `DetailsId` is stored and is not the key. `PriceSnapshot` is keyed by league, item, and UTC hour bucket. A timestamp written into that key is truncated to the UTC hour, and the table rejects a value that is not already on that hour. The snapshot stores chaos value, divine value, and listing count. Chaos value is `numeric(18,4)`. Divine value is `numeric(18,8)` so an item worth a fraction of a chaos keeps a nonzero divine price. Migration `AddLeagueItemPriceSnapshot` creates those three tables. Migration `AddSnapshotIconAndSparkline` adds nullable `PriceSnapshots.Icon` and required `PriceSnapshots.Sparkline` (`numeric[]`, default empty). Icon is the poe.ninja image stored with that hour's snapshot.
- `InvestingExile.Pipeline` is a .NET 8 console app under `backend/`. It references Domain. It holds the price ingest command (issue #5): `dotnet run --project InvestingExile.Pipeline -- --league "<name>"`. `PriceIngestService` fetches poe.ninja prices through the `IPoeNinjaClient` seam (`PoeNinjaHttpClient` is the live client) and, in one transaction, upserts the League by name, Items by category + name + variant, and a PriceSnapshot per item at the current UTC hour. Re-running in the same hour updates the snapshot in place; it does not insert a second item or snapshot. It targets poe.ninja's 2026 currency-exchange endpoint (`economy/exchange/current/overview`) and ingests every PoE1 exchange type, not just Currency/Scarab/Fragment. `ChaosValue` is the line's `primaryValue`; `DivineValue` is derived from `core.rates.divine`; Chaos Orb and Divine Orb come from `core.items`; `ListingCount` is left null because the exchange exposes trade volume, not a listing count. Each line's `sparkline.data` is stored on that snapshot as `numeric[]`. A null sample is kept as a gap in that series. The poe.ninja `image` is stored on that same snapshot as `Icon`. Item category is poe.ninja's own `category` (so Scarabs land under Fragments). The connection string comes from `INVESTINGEXILE_CONNECTION` with the compose default as fallback. A manual double-run against the live league `Allflame` persisted 1 league, 696 items, and 696 snapshots, unchanged by the second run.
- `InvestingExile.Api` is the .NET 8 HTTP read API under `backend/`. It references Domain and reads Postgres through the same `INVESTINGEXILE_CONNECTION` fallback as the pipeline (`ConnectionStrings:InvestingExile` overrides it). Swagger uses OpenAPI 3.0.1. `GET /items` returns each item's latest snapshot: name, category, variant, icon, chaos value, divine value, listing count, sparkline points, and the snapshot hour. Latest means the greatest UTC hour, then the greater league id. An item with no snapshot is left out. The response sets `Cache-Control: no-store`. There is no response cache.
- `InvestingExile.Tests` is the xUnit project under `backend/`. Issue #6 is the double-run test: `PriceIngestDoubleRunTests` runs `PriceIngestService` twice against Testcontainers Postgres 16, feeding `Fixtures/currency-overview.json` through `IPoeNinjaClient`. The second body keeps the same item and raises chaos from 10 to 25. The test asserts one league, one item, one snapshot for the current UTC hour, and chaos 25. `PriceIngestMappingTests` feeds `Fixtures/exchange-currency-core.json` (`core.rates.divine` 0.004) and checks those mapping rules: an Exalted Orb at 10 chaos stores divine 0.04, Chaos Orb and Divine Orb are seeded once (chaos 1 and 250) even when every exchange type returns that core, a failed fetch writes no league, item, or snapshot, and a line's image and `sparkline.data` are stored.
- `frontend/` is a Vite, React, and TypeScript app. `npm run dev` serves a page titled InvestingExile and an empty `#item-grid` region. The shell has no item cards and does not call the API.
- `docker-compose.yml` runs Postgres 16. The database name is `investingexile`. The API, pipeline, and frontend are not in that compose file.
