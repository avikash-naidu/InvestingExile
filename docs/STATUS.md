# Status

This file is the single source of truth for what InvestingExile contains. Every commit updates this file in the same commit.

## Now

- `backend/InvestingExile.sln` is a .NET 8 solution.
- Projects in that solution: InvestingExile.Domain, InvestingExile.Pipeline, InvestingExile.Api, InvestingExile.Tests.
- `InvestingExile.Domain` is the class library under `backend/`. It holds `League`, `Item`, `PriceSnapshot`, and `AppDbContext`. Item identity is category + name + variant. `DetailsId` is stored and is not the key. `PriceSnapshot` is keyed by league, item, and UTC hour bucket. A timestamp written into that key is truncated to the UTC hour, and the table rejects a value that is not already on that hour. The snapshot stores chaos value, divine value, and listing count. Chaos value is `numeric(18,4)`. Divine value is `numeric(18,8)` so an item worth a fraction of a chaos keeps a nonzero divine price. Migration `AddLeagueItemPriceSnapshot` creates those three tables. Migration `AddSnapshotIconAndSparkline` adds nullable `PriceSnapshots.Icon` and required `PriceSnapshots.Sparkline` (`numeric[]`, default empty). Icon is the poe.ninja image stored with that hour's snapshot.
- `InvestingExile.Pipeline` is a .NET 8 console app under `backend/`. It references Domain. It holds the price ingest command (issue #5): `dotnet run --project InvestingExile.Pipeline -- --league "<name>"`. `PriceIngestService` fetches poe.ninja prices through the `IPoeNinjaClient` seam (`PoeNinjaHttpClient` is the live client) and, in one transaction, upserts the League by name, Items by category + name + variant, and a PriceSnapshot per item at the current UTC hour. Re-running in the same hour updates the snapshot in place; it does not insert a second item or snapshot. It targets poe.ninja's 2026 currency-exchange endpoint (`economy/exchange/current/overview`) and ingests every PoE1 exchange type, not just Currency/Scarab/Fragment. `ChaosValue` is the line's `primaryValue`; `DivineValue` is derived from `core.rates.divine`; Chaos Orb and Divine Orb come from `core.items`; `ListingCount` is left null because the exchange exposes trade volume, not a listing count. Chaos Orb and Divine Orb are seeded from the first `core` that contains each id, so an earlier core that omits them does not block a later type. After a successful fetch, ingest takes one Postgres session advisory lock (`PipelineWriteLock`), then applies EF migrations and runs the write transaction, and releases the lock after commit or rollback. Two overlapping ingests therefore write one after the other: both finish, with one league, one item, and one snapshot per key. The fetch stays outside the lock. If unlock fails on a live connection, that connection is dropped from the Npgsql pool so its session, and the lock, end. A failed fetch still writes no league, item, or snapshot. An empty body from every exchange type, the response poe.ninja gives for an unknown league, throws before the write and leaves the database unchanged. Each line's `sparkline.data` is stored on that snapshot as `numeric[]`. A null sample is kept as a gap in that series. The poe.ninja `image` is stored on that same snapshot as `Icon`. Item category is poe.ninja's own `category` (so Scarabs land under Fragments). The connection string comes from `INVESTINGEXILE_CONNECTION` with the compose default as fallback. A manual double-run against the live league `Allflame` persisted 1 league, 696 items, and 696 snapshots, unchanged by the second run.
- `InvestingExile.Api` is the .NET 8 HTTP read API under `backend/`. It references Domain and reads Postgres through the same `INVESTINGEXILE_CONNECTION` fallback as the pipeline (`ConnectionStrings:InvestingExile` overrides it). Swagger uses OpenAPI 3.0.1. `GET /items` returns each item's latest snapshot: name, category, variant, icon, chaos value, divine value, listing count, sparkline points, and the snapshot hour. Latest means the greatest UTC hour, then the greater league id. An item with no snapshot is left out. The response sets `Cache-Control: no-store`. There is no response cache.
- `InvestingExile.Tests` is the xUnit project under `backend/`. Issue #6 is the double-run test: `PriceIngestDoubleRunTests` runs `PriceIngestService` twice against Testcontainers Postgres 16, feeding `Fixtures/currency-overview.json` through `IPoeNinjaClient`. The second body keeps the same item and raises chaos from 10 to 25. The test asserts one league, one item, one snapshot for the current UTC hour, and chaos 25. Issue #61 adds two tests there that start two ingests at once on separate contexts, one after the schema is dropped and one on a current schema. Each asserts one league, one Exalted Orb item, and one snapshot for that hour at chaos 10. `PriceIngestMappingTests` feeds `Fixtures/exchange-currency-core.json` (`core.rates.divine` 0.004) and checks those mapping rules: an Exalted Orb at 10 chaos stores divine 0.04, Chaos Orb and Divine Orb are seeded once (chaos 1 and 250) even when every exchange type returns that core, a failed fetch writes no league, item, or snapshot, an empty overview for every exchange type writes nothing, a line's image and `sparkline.data` are stored, ingest creates the schema when it has been dropped, and Chaos Orb and Divine Orb still appear when only a later exchange type's core contains them.
