# Status

This file is the single source of truth for what InvestingExile contains. Every commit updates this file in the same commit.

## Now

- `backend/InvestingExile.sln` is a .NET 8 solution.
- Projects in that solution: InvestingExile.Domain, InvestingExile.Pipeline, InvestingExile.Api, InvestingExile.Tests.
- `InvestingExile.Domain` is the class library under `backend/`. It holds `League`, `Item`, `PriceSnapshot`, and `AppDbContext`. Item identity is category + name + variant. `DetailsId` is stored and is not the key. `PriceSnapshot` is keyed by league, item, and UTC hour bucket. A timestamp written into that key is truncated to the UTC hour, and the table rejects a value that is not already on that hour. The snapshot stores chaos value, divine value, and listing count. Chaos value is `numeric(18,4)`. Divine value is `numeric(18,8)` so an item worth a fraction of a chaos keeps a nonzero divine price. One migration, `AddLeagueItemPriceSnapshot`, creates those three tables.
- `InvestingExile.Pipeline` is a .NET 8 console app under `backend/`. It references Domain. It holds the price ingest command (issue #5): `dotnet run --project InvestingExile.Pipeline -- --league "<name>"`. `PriceIngestService` fetches poe.ninja prices through the `IPoeNinjaClient` seam (`PoeNinjaHttpClient` is the live client) and, in one transaction, upserts the League by name, Items by category + name + variant, and a PriceSnapshot per item at the current UTC hour. Re-running in the same hour updates the snapshot in place; it does not insert a second item or snapshot. It targets poe.ninja's 2026 currency-exchange endpoint (`economy/exchange/current/overview`) and ingests every PoE1 exchange type, not just Currency/Scarab/Fragment. `ChaosValue` is the line's `primaryValue`; `DivineValue` is derived from `core.rates.divine`; Chaos Orb and Divine Orb come from `core.items`; `ListingCount` is left null because the exchange exposes trade volume, not a listing count. Item category is poe.ninja's own `category` (so Scarabs land under Fragments). The connection string comes from `INVESTINGEXILE_CONNECTION` with the compose default as fallback. A manual double-run against the live league `Allflame` persisted 1 league, 696 items, and 696 snapshots, unchanged by the second run.
- `InvestingExile.Api` is the .NET 8 HTTP read API under `backend/`. It references Domain. Its `Program` builds and runs with no routes. Swagger uses OpenAPI 3.0.1. `GET /items` is still issue #8.
- `InvestingExile.Tests` is the xUnit project under `backend/`. Issue #6 is the double-run test: `PriceIngestDoubleRunTests` runs `PriceIngestService` twice against Testcontainers Postgres 16, feeding `Fixtures/currency-overview.json` through `IPoeNinjaClient`. The second body keeps the same item and raises chaos from 10 to 25. The test asserts one league, one item, one snapshot for the current UTC hour, and chaos 25.
- `docker-compose.yml` runs Postgres 16. The database name is `investingexile`. The API, pipeline, and frontend are not in that compose file.
- Tests check that the solution lists those four projects and no others, that Domain is a class library with the price model and `AppDbContext`, that an item is unique on category + name + variant, that a snapshot is unique on league + item + hour bucket, that divine value has scale 8 and chaos value scale 4, that one migration creates those three tables, that Pipeline is that console app carrying the ingest command (poe.ninja call, `HttpClient`, `--league`) and no patch-note parsing, that Api is that web host without an item route, that the xUnit project is an xUnit test project, and that the compose file uses `postgres:16` with database `investingexile`. `PriceIngestDoubleRunTests` proves the same-hour upsert against a saved currency-exchange fixture.
